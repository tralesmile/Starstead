# Lessons (mistakes and guards, read at the start of each run)

- Godot 4.3 direct download: https://github.com/godotengine/godot/releases/download/4.3-stable/Godot_v4.3-stable_linux.x86_64.zip works via curl. Run tests: `~/bin/godot --headless --path . -s tests/run_tests.gd` (run `--import` first on a fresh clone).
- After adding a new `class_name` script run `godot --headless --path . --import` BEFORE tests, else "identifier not declared" errors. The runner (-s mode) cannot compile scripts referencing autoloads (GameState): keep testable logic in pure classes (PlayerMath, HudText, DayNight) and keep autoload use in nodes.
- Screenshots: `tools/screenshot.sh` (xvfb + --write-movie) writes /tmp/mv*.png; view with Read. `-s` script screenshots do not work (autoloads missing).
- JSON numbers load as floats: `int in json_array` is false in Godot; compare with int(x) in a loop.
- Shader compile errors never show in headless runs or tests: always run tools/screenshot.sh after shader edits (it greps "SHADER ERROR") and look at the frame. A blank beige screen = shader failed.
- Screenshot helper args: `tools/screenshot.sh 20 -- --zoom=1 --at=x,y` (tile coords) to inspect any spot.
- Canvas shaders: in fragment(), COLOR already includes the texture; multiplying by texture again kills outlines. Pass modulate via a varying from vertex(). `return` is not allowed in fragment().
- Nested y-sort did not merge here: put the player under the same y-sorted parent (World) as the props.
- New class_name scripts need `--import` before tests, else the test file 'cannot load'. GDScript: float % float is invalid, use fposmod. Night glow under CanvasModulate: divide colour by DayNight.tint to cancel it.
- CharacterBody2D defaults to GROUNDED motion mode: vehicles need MOTION_MODE_FLOATING; a car that carries the player must add_collision_exception_with(player) both ways or it jitters/flies off.
- The test runner prints SCRIPT ERROR / parse errors yet still says 0 failed: ALWAYS run `... 2>&1 | grep -E "ERROR|FAIL|TESTS"` and fix every ERROR line. Typed `var x := [..][i]` on array literals fails to infer: annotate `var x: float`.
- ColorRect under a CanvasLayer has size 0 (anchors need a Control parent): set .size = get_viewport_rect().size, and verify overlays by pixel diff (python PIL getpixel) not by eye; pastel overlays look like 'no change'.
- Clock has no class_name (use GameState.clock.DAYS_PER_SEASON). gen_items.py now keeps old icons for ids it does not draw; new item ids go at the END of data/items.json so icon indexes stay stable. Two scheduled runs can overlap: git pull --rebase before every push and check git log for duplicate work before starting an item.
- World (and anything a test compiles) must not reference autoloads: pass things in (World.nodes_ref). A strong reference cycle between RefCounted objects (WorldGen <-> ChunkStream) prints "resources still in use at exit" and fails check.sh: use weakref on the back-pointer.
- Seams between ground-shader chunks: pad the data texture with the neighbours' edge cells (World.data_image pad=1); clamped edges show a visible line.
- A GDScript subclass that defines its own _init() must call super._init() first, or the parent never builds its nodes (SmeltView: canvas was null). Rooms/mines far from the map need Player.indoors, else the out-of-world sdf reads as deep water (shore slowdown, reflection ghost).
- A screenshot far from the feature looks like 'nothing rendered': when --at shows plain meadow, check the distance in cells (zoom 1 = 20x11 cells) before debugging; screenshot several spots around a new area.
- Tyre marks last 40 s on the circuit (VehicleMath.skid_life), 6 s elsewhere. Check each new CarView member against test compile: CarView refers to CircuitModel/DriftScore class_names, so run --import before tests.
- A CanvasItem that only calls queue_redraw while active keeps its last frame when it goes idle: redraw once on every state change (the K log looked stuck open). Owner playtest beats agent screenshots: read docs/PLAYTEST.md owner entries first each run.
- `cat >> tests/x.gd` on a file that does not exist creates a headless test without `extends BaseTest`: check the file list first. Subagents sharing one working tree worked fine when each owned distinct files and main.gd was only touched with tiny Edits.
- UI must live under a CanvasLayer: a Label added straight to main (a Node2D) is drawn in WORLD space and never shows once the camera moves (the toast was invisible for many runs; screenshots near the origin hid it). When a message "does not show", check its parent first. The interaction prompt had the same bug (fixed run 14): grep `add_child(` of every Label/Control in main.gd when adding UI. Two labels at the same screen spot (toast + goal line) hide each other: give one priority.
- Push can fail when the session has no linked GitHub account (proxy 403): keep committing locally and hand over a git bundle; never lose the work.
- Setting CPUParticles2D.amount every frame restarts the emitter (no particles ever show): assign it only when the value changes.
- A parse error in a new view script is invisible to unit tests that never load it; always run a --xyz-demo screenshot (SCRIPT ERROR lines) before trusting a green test run. `var x := {...}[key]` cannot infer a type: write `var x: String = ...`.
- A ternary like `a.emit() if x else b.emit()` fails at runtime ("return value of a method that returns void") and a demo that never took that branch hid it: use if/else, and make demo flags force the success path (set the odds) so the screenshot exercises it.
- New class_name files need `godot --headless --import` before tools/screenshot.sh, else main.gd fails to parse (run 34).
- Again (run 35): `cat >> tests/x.gd` on a missing file creates a test without `extends BaseTest`; `ls tests | grep name` first. Demo placements must be near the player at the chosen zoom (zoom 3 shows only ~7x4 cells).
- Run 37: `godot` is not on PATH in a fresh container, only ~/bin/godot: a bare `godot --import` fails silently and then new class_names are 'not declared'. Always call ~/bin/godot.
- Run 38: menus that list data/*.json grow silently past the 360px screen: give every list a layout test (see CraftGrid test). Pure layout/logic used by tests must live outside classes that mention GameState (Hotbar, CraftView).
- Run 38: tools/check.sh now takes more than 10 minutes: start it in the background (`tools/check.sh > /tmp/check.log 2>&1 &`) and wait, a foreground call times out.
- Run 39: tests/test_chunks.gd pins chunk -> region ids, so a new place inside an existing region should be a cell-level override (IsleModel.RECT for the banner), not a new regions.json entry.
- Run 39: screenshots cannot verify audio: use `--sfx-log` (prints Sfx.play_counts + ambience) after wiring a sound. A bow QA flag must append "bow" to tools_owned or the slot stays the club.
- Run 39: cinematic overlays must sit above RegionBanner (layer >= 60), else a teleport prints the old region name over them.
- Run 40: fixed-timestep sims must latch one-shot inputs until a tick actually runs; a frame shorter than 1/60 s runs no tick and silently eats the key press.
- Run 40: any new input-grabbing overlay must be routed ABOVE the map/story/journal/bag handlers in Main._unhandled_input, or Tab/M/J/K open on top of it. Pure layout constants used by tests belong in the model class (ShopMenu), not the view (GameState does not compile in tests).
- Run 41: "[ ] next:" notes in PLAN go stale (tyre squeal had existed for many runs): grep for the feature before building it. InteriorModel.action_near now returns the NEAREST furniture, so adjacent usable pieces work.
- Run 42: test the player's real path, not just the model: save/load had unit tests but main never called load_game for 41 runs. For any system with two halves (save/load, open/close, earn/spend) grep for BOTH call sites and keep one in-game check in tools/check.sh. A plain launch loads user://save.json, so QA screens without other flags must pass --fresh.
- Run 44: give a feature subagent a time box in its brief (one took 96 min). A test value must be inside the game's limits (VehicleMath.FUEL_MAX is 40, so a saved 41 was clamped and the check failed). When shader and game logic must agree on a pattern (puddles), generate it once in GDScript and pass it to the shader as a texture.
- Run 45: ask 'how does a player stop playing?' in playtests: there was no quit/pause and closing lost the day. Demo screens never show a missing screen.
- Run 45: do not add code or tests while tools/check.sh is running. Parallel screenshot users must set SHOT_DIR.
- (run 46) tools/check.sh now takes about 18 minutes, longer than a foreground command may run: start it with nohup in the background and poll /tmp/check.log.
- (run 46) Tell parallel subagents plainly not to chain git or delete commands onto their test commands; one denied part blocks the whole command.
